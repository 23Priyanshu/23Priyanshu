1. Purpose of Database System
To efficiently store, retrieve, and manage large amounts of data.

Ensures data consistency, integrity, and security while reducing redundancy.

2. Characteristics of Database Approach
Data Abstraction: Simplifies data by hiding complex details.

Data Independence: Changes in data structure don’t affect applications.

Centralized Control: Ensures consistency and security of data.

3. Data Models
Frameworks to define the structure of data.

Examples:

Hierarchical Model: Data organized in a tree-like structure.

Relational Model: Data in tables (rows and columns).

Object-Oriented Model: Data as objects with attributes and methods.

4. Database Management System (DBMS)
A software system to interact with databases.

Functions: Data storage, retrieval, manipulation, and security management.

5. Database System Architecture
The design/structure of a DBMS.

Typically follows client-server architecture with components like query processing, storage, etc.

6. Three-Schema Architecture
External Schema: User view of the data.

Conceptual Schema: Logical structure of the database.

Internal Schema: Physical storage of the data.

7. Components of DBMS
Hardware: Physical devices for data storage.

Software: The DBMS itself.

Data: The information stored.

Users: Administrators, developers, and end-users.

Procedures: Instructions for handling the database.

8. Data Independence
Logical Independence: Changes in the logical schema don’t affect external views.

Physical Independence: Changes in data storage don’t affect the logical schema.

9. File System Approach vs Database System Approach
File System:

Data stored in flat files.

High redundancy, weak data security.

Database System:

Centralized management of data.

Reduces redundancy, improves consistency and security.

1. Motivation
Conceptual data modeling provides a high-level, abstract view of the data structure. It helps:

Visualize real-world entities and their relationships.

Simplify database design.

Ensure clarity before physical implementation.

2. Entities
Entities are objects or concepts in the real world represented in the database. For example:

Person, Car, Building, etc.

3. Entity Types
Entity types define a group of similar entities and their attributes. Example:

An entity type Student represents all students, with attributes like Name and Roll Number.

4. Attributes
Attributes are properties or characteristics of an entity. For instance:

Name, Age, Address for the entity Person.

5. Relationships
Relationships define associations between entities. Example:

A Student "enrolls" in a Course.

6. Relationship Types
Categorization of relationships based on how entities are associated:

One-to-One: Each entity in Set A relates to one entity in Set B.

One-to-Many: An entity in Set A relates to many entities in Set B.

Many-to-Many: Entities in Set A relate to multiple entities in Set B.

7. Constraints on Relationships
Defines rules or limitations for relationships:

Cardinality Constraints: Specifies the number of entity instances involved (e.g., 1-to-1 or 1-to-many).

Participation Constraints: Specifies whether an entity’s participation is mandatory or optional.

8. Entity Relationship Diagram (ERD) Notation
ERD is used to visually represent entities, attributes, and relationships. Common notations include:

Rectangle: Represents an entity.

Oval: Represents attributes.

Diamond: Represents relationships.

Lines: Connect entities to relationships.

1. Update Anomalies
Update anomalies occur when data changes lead to inconsistencies or redundancies in a database. They include:

Insertion Anomaly: Cannot add data due to missing related data.

Deletion Anomaly: Unintentionally lose data when deleting records.

Modification Anomaly: Updating data in multiple places leads to errors.

2. Relational Data Model
The relational data model organizes data in tables (called relations) with rows (tuples) and columns (attributes). It ensures structured and efficient data handling.

3. Schema-Instance Distinction
Schema: The blueprint or design of a database (structure).

Instance: The actual data stored in the database at a specific point in time.

4. Keys
Keys are attributes used to identify records uniquely:

Primary Key: Uniquely identifies each row in a table.

Candidate Key: A potential primary key (unique, but not selected).

Composite Key: Combines multiple attributes to create uniqueness.

5. Relational Integrity Constraints
Rules that ensure data correctness:

Entity Integrity: Primary keys must be unique and not null.

Referential Integrity: Foreign keys must reference valid primary keys.

6. Referential Integrity and Foreign Keys
Referential integrity ensures that a foreign key's value matches a primary key value in the referenced table. It prevents invalid references.

7. Relational Algebra Operators
Relational algebra provides formal operators for querying data:

Selection (σ): Filters rows based on conditions.

Projection (π): Extracts specific columns.

Union (∪): Combines results of two queries.

Intersection (∩): Finds common rows between queries.

Difference (-): Retrieves rows in one query, not in the other.

Join (⨝): Combines tables based on a related column.
